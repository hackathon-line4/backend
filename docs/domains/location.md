# location — 위치 확인

**담당:** 조한결
**범위:** 마지막 위치 조회, 위치 새로고침 요청/상태, 위치 보내기(당사자) (P-1)

## 현재 구현

- 위치 확인 도메인 모델 `location_requests` / `last_locations` (#26). API 레이어는 `link`·`settings` 구현 후
- **위치는 쌓지 않는다.** 당사자당 마지막 1건만 덮어써 보관하고 이동 경로·과거 위치는 남기지 않는다 — 그래서 `last_locations`는 당사자 ID가 그대로 기본 키다. 공유를 끄면 이 행을 지운다
- 좌표를 덮어쓰면 **주소를 함께 지운다**. 좌표만 바뀌고 옛 주소가 남으면 지도와 주소가 어긋난다. 주소는 변환이 끝난 뒤 다시 채운다
- 좌표는 `double`이 아니라 `BigDecimal(9,6)` — 소수점 6자리가 지도에 찍히는 값이다(recipient의 `CapturedLocation`과 같은 이유)
- 새로고침 요청 상태는 `PENDING` → `FULFILLED`/`FAILED`/`TIMED_OUT`. **끝난 요청은 나중 응답이 되돌리지 않는다** — 보호자 화면이 이미 결과를 보여 줬기 때문이다
  - 다만 **시간 초과 뒤에 온 위치도 마지막 위치에는 반영한다**(위치 보내기 API). 요청 상태와 위치 저장을 따로 판단하도록 `markFulfilled()`가 "이번에 완료됐는지"를 돌려준다
- `location_requests`도 `timeoutAt`을 컬럼으로 들고 있어 서버가 재시작해도 판정이 남는다(messaging 타이머와 같은 구조)

- 새로고침 요청 상태 조회 `GET /location-requests/{requestId}`와 시간 초과 타이머 (#33)
  - 시간 초과 판정을 **두 군데**에서 한다. 조회 시점(명세가 요구 — 폴링하는 보호자를 기다리게 하지 않는다)과 스윕(아무도 조회하지 않는 요청 정리)
  - 늦게 도착한 위치가 먼저 반영됐다면 `markTimedOut()`이 스스로 건너뛰므로 스윕이 결과를 되돌리지 않는다
  - 요청 제한 시간(30초 제안)은 요청을 **만들 때** 정해지므로, 설정값은 생성 API가 들어올 때 추가한다

- 위치 보내기 `POST /location-requests/{id}/fulfill` (#87). 당사자 본인만, 남의 요청이면 404
  - **공유가 꺼져 있으면 좌표가 와도 저장하지 않고** `FAILED`/`SHARING_OFF`. 호출자가 당사자 본인이라 `LocationSharingService.get`으로 확인한다
  - **시간 초과된 요청이어도 늦게 온 위치는 마지막 위치에 반영한다.** 보호자 화면은 이미 '실패'를 보여 줬지만 위치를 버릴 이유는 없다 — 요청 상태만 되돌리지 않는다
  - 실패 보고는 마지막 위치를 지우지 않는다. 이번에 못 얻었다고 예전 위치가 사라질 이유가 없다
  - 좌표 없이 실패 사유도 없으면 400 — 성공 보고인데 좌표가 빠진 경우다

- 위치 새로고침 요청·마지막 위치 조회 (#91). 보호자만, 구성원이 아니면 404
  - **진행 중인 요청이 있으면 새로 만들지 않고 그것을 돌려준다** — 버튼을 여러 번 눌러도 당사자 기기가 여러 번 깨지 않는다
  - 기한이 지난 요청은 '기다리는 중'에서 뺀다. 새로고침(쓰기 경로)에서는 그 자리에서 끝내고 새 요청을 만들고, **조회는 읽기만 한다** — 전이는 쓰기 경로와 스윕이 맡는다
  - 공유가 꺼져 있으면 요청은 409 `LOCATION_SHARING_OFF`, 조회는 **저장된 위치가 남아 있어도 `last`를 주지 않는다**
  - 공유 상태는 `LocationSharingService.isSharingEnabled`로 읽는다(#88)

- SSE 이벤트 발행 (#95)
  - `location_request.created` → **당사자**에게. 요청 내용은 당사자에게 필요 없어 `requestId`만 보낸다(명세 그대로). 진행 중인 요청을 그대로 돌려줄 때는 발행하지 않는다 — 기기를 다시 깨우지 않기 위해서다
  - `location_request.updated` → **보호자**에게. 실패·시간 초과에서 보낸다. 스윕은 실제로 전이된 요청만 발행한다
  - `location.updated` → **보호자**에게. 어느 요청의 답인지 `requestId`를 함께 보내 '요청 중' 표시를 끝낼 수 있게 한다. 시간 초과로 이미 끝난 요청에 늦게 도착한 위치도 보낸다 — 보호자에게는 그래도 새 위치다
  - 조회(마지막 위치·요청 상태)에서 일어나는 시간 초과 전이는 발행하지 않는다 — 그 응답을 보호자가 지금 받고 있다

### 후속 작업 (해당 기능 구현 시)

- 공유 해제 시 마지막 위치 삭제 — `settings`와 호출 방식 합의 필요
- 주소 변환(좌표 → 주소) — 지도 API 업체·키 미정. 그동안은 `address: null`(명세가 허용)
